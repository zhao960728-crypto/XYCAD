# 输入与资源上限：数值和原因

更新：2026-11-07。XYCAD 目前仅供应急预览，仍在持续做格式兼容和功能完善。

**以下上限是当前程序设置的资源与复杂度保护值，不是对应 CAD 格式的官方最大能力。** 文件的压缩率、图元/曲面复杂度、重复实例及电脑资源都会影响结果。小于上限也可能因为未兼容的内容而失败，大于某条预算也不表示原文件损坏。表内 MiB 为 1024 × 1024 字节。

上传文件大小、解压后大小、解析记录数量、网格大小和导出计算量是不同的指标。例如，几十 MiB 的压缩图纸可能展开出数百 MiB 的数据，几 MiB 的复杂曲面也可能比大尺寸的简单网格更难解析。

## 文件、解压与格式读取

| 适用范围 | 当前上限或行为 | 为什么设置 | 超限影响 |
| --- | --- | --- | --- |
| 一般上传入口 | 没有统一的上传字节上限；先流式写临时文件 | 避免用一个文件大小门槛误拦不同类型的正常文件 | 仍受临时磁盘、可用内存、网络与后续格式预算限制，不能理解为无限上传 |
| 解析进程读取文件 | 不超过 Node.js Buffer 容量与当时可用内存的较小值 | 部分解析需要完整输入驻留内存，防止明显无法分配的读取 | 返回内存不足；该检查不是整个解析过程的内存峰值保证 |
| DWG/DWT | 主要解压页/相关数据段预算 256 MiB，索引最多 100 万条；具体版本路径还有自身校验 | 压缩内容展开后及对象索引可能占用大量内存；避免异常声明触发过量分配和遍历 | 转换或预览失败；若原件有内嵌图，部分情况降级显示内嵌图 |
| DWG/DWT 转 DXF | 生成的 DXF 最多 256 MiB | 文本化导出可能比输入大很多，限制序列化、传输和回读成本 | 拒绝超预算转换，不是 DWG 输入统一限 256 MiB |
| EXB | 累计解压 256 MiB；15 万记录、10 万绘制项、45 万几何段、75 万文字字符 | 同时限制压缩膨胀、对象扫描和浏览器绘制负担 | 报读取/预览容量问题；部分文件可显示内嵌图 |
| DWFx / 3MF 包容器 | 累计解压 256 MiB | ZIP 内多个压缩项合计可能远大于上传文件，限制累计展开内存 | 拒绝读取超预算包 |
| DWFx 页面 | 最多 64 页；每个读取部件最多 10 万元素 | 多页 XML 路径解析和页面图元会累积内存与渲染开销 | 拒绝超预算页面内容，不代表 DWFx 格式只能有 64 页 |
| SLDDRW 页数与记录 | 最多 64 页；记录候选最多 10 万，解压尝试最多 512 次 | 限制多页内容、记录扫描及重复解压成本 | 报读取预算问题或无法形成完整预览/导出 |
| SLDDRW 压缩数据 | 单个几何记录最多 64 MiB；其他画面记录最多 8 MiB；累计解压最多 96 MiB | 缓存记录与图片展开后可能大量占用内存，分别限制单记录与总量 | 部分超限记录不读取，累计超限报错；可能导致内容不完整 |
| SLDDRW 保存画面 | 宽高各最多 4096，单图最多 800 万像素，整套最多 6400 万像素 | 图片解码和 PDF 导出按像素占内存，文件字节小也可能很昂贵 | 画面不可用或导出被拒绝；这不是矢量图纸的最大物理尺寸 |
| SLDDRW 矢量内容 | 相关读取阶段最多 10 万图元、256 个视图、30 万视图顶点 | 限制保存缓存解析、视图配准及输出图元规模 | 报矢量或模型视图预算问题，不会自动重建缺失视图 |
| SLDPRT 输入与转换 | 输入、单条选中记录、几何流及生成 STEP 各有 64 MiB 检查；选中配置相关流累计解压最多 128 MiB | 离线转换要展开保存分区并生成 STEP，可能同时持有多份数据；避免内存与输出膨胀 | 拒绝超预算输入/转换，和其他格式的上传策略不同 |
| SLDPRT 实体/配置 | 所选配置最多 256 个实心实体；返回配置清单最多 256 项 | 当前离线转换及完整性核验按实体与配置逐项处理，限制展开和核验工作量 | 拒绝超出当前读取范围的结果；不将读取到的子集冒充完整配置 |
| STEP 记录 | 默认 100 万记录/1200 万参数值；共享装配读取输入达到 64 MiB 时采用 300 万记录/3200 万参数值预算 | 文本实体展开为对象与引用后比原字节更占内存；给大装配保留单独预算 | 报实体或参数容量问题；不同读取路径的预算不相同 |
| Parasolid X_T/X_B 记录 | 当前节点解析最多 100 万条；实例与层级遍历另有保护 | 防止节点图、重复/循环引用和展开遍历失控 | 读取失败或只显示可读部分；不表示所有布局在此规模内都兼容 |

## 几何、网格与出图

| 适用范围 | 当前上限或行为 | 为什么设置 | 超限影响 |
| --- | --- | --- | --- |
| DXF / DWG 常规二维场景 | 配置上限为 30 万绘制项、100 万几何段、120 万文字字符；模型记录预算 30 万，部分内部调用有更小默认值 | 块展开、曲线分段、文字排版和 SVG 绘制会放大原图对象数量 | 拒绝超过场景容量的展开；大图应分区、拆块或精简对象 |
| 旧整场景网格路径 | 最多 50 万三角面；网格格式相关读取还限制 75 万顶点/20 万实例 | 整场景会展开重复实例并传送到浏览器，限制服务端数组、传输、GPU 和拾取计算规模 | 报网格/实例容量问题；与共享网格路径的预算不同 |
| STEP/X_T 共享网格路径 | 单个零件最多 100 万面，所有不同零件累计最多 500 万面 | 重复实例可共享网格，但每份实际网格仍占 CPU/GPU 内存并有生成成本 | 个别零件无法生成几何，或装配只能部分显示；按界面缺件提示判断完整性 |
| 多边形、边界和样条 | 多处单环/多边形/交线采样上限为 16384；STEP/Parasolid 单张样条控制网格也有 16384 点检查 | 三角剖分、曲线拟合及参数面求值成本会随边界和控制点数量快速增加 | 报局部几何容量或兼容问题，即使总文件很小也可能触发 |
| 曲面求值 | STEP 样条每次求值成本检查为 300 万；Parasolid 相应成本检查默认 1200 万，部分路径 2400 万 | 这些是内部求值成本估计，限制复杂高阶曲面的运算量，不是文件字节数或曲面精度指标 | 拒绝/尝试其他已适配求值路径；不能通过降低拓扑核验要求来保证打开 |
| 三视图输入 | 最多 20 万三角面 | 可见线和遮挡关系比普通显示更昂贵，限制投影分析成本 | 拒绝整套出图，可尝试较小的完整装配节点 |
| 三视图遮挡与输出 | 遮挡查询节点访问最多 4500 万次；单视图线条最多 10 万；输出图元最多 18 万 | 即使三角面数相同，互相遮挡和线条碎片数量也可能差很多，需独立控制计算及导出成本 | 拒绝超预算出图，不应省掉遮挡计算后声称结果完整 |

## 服务处理时间、并发与缓存

| 限制 | 当前值 | 原因与影响 |
| --- | --- | --- |
| 解析超时 | 一般任务 30 秒；非大图 Parasolid 60 秒；装配任务 180 秒；大图其他任务按 `min(300, 60 + floor(字节数 / 16 MiB))` 秒 | 防止极慢或不收敛的解析长期占用工作进程；SLDPRT 离线转换另有 30 秒限制。超时会中止，不能保证大文件都能在时限内完成 |
| 解析进程 V8 堆预算 | 普通任务 768 MiB，大图任务 2048 MiB | 限制单个 Node.js 工作进程的 JS 堆增长。不是输入上限，也不是进程总内存硬上限；Buffer、原生分配与 Python 另占内存 |
| 并发 | 工作槽为 `min(4, max(1, CPU 可用并行数 − 1))`；达到 4 MiB 的输入进入大图路径，同一时刻只处理一份大图 | 预留主服务资源，避免多个大解析同时耗尽内存。繁忙时返回 503。4 MiB 是调度阈值，不是文件大小上限 |
| 装配缓存 | 最多 8 份资产，空闲约 30 分钟过期 | 限制派生网格临时磁盘占用；容量回收、过期或重启后需重传。它不是永久文件库 |
| HTTP 超时 | 请求头约 10 秒；上传连接空闲约 120 秒；结果发送空闲约 60 秒 | 防止连接无限占用；不是所有任务必须在 120 秒内处理完。持续传输、上传完成后的计算和解析超时分别处理 |

多数预算目前是源码常量，没有统一的“取消全部限制”环境变量。可根据部署电脑资源和实际文件调整，但应同时检查单项与累计预算、进程内存、超时、浏览器负载，并用目标文件验证内容完整性。**增加上限不等于修复格式兼容或保证尺寸正确。** 无效长度、循环引用、损坏记录、几何一致性等正确性检查不能当成容量限制直接关闭。
